## Implemented walkthrough and evidence

Use the isolated launch in [mock frontend](mock-frontend.md), sign in as synthetic `Demo.Owner` with `synthetic password`, load groups and select Synthetic Friday friends. The Add panel shares the mounted library store. Manual Save requires a mood and valid full/typical duration; episodic entries additionally require numbering and the typical-duration checkbox. Load library to inspect the actual saved entry and Mine contribution. Existing personal history remains readonly.

Choose YouTube title/link or Kinopoisk title, search, then explicitly choose a candidate. The chosen lookup input kind is authoritative: Title search always returns a candidate page (or a named empty/failure outcome) and never applies a review, even for text shaped like an 11-character video ID such as `WatchNextQA`; only the YouTube link/video-ID kind strictly parses and resolves a link or ID directly. Next/Previous retain a service-owned chain with at most five visits. Clean selection fills supported editable fields directly; no Apply step exists. Mood choices remain manual. A dirty draft requires Replace details or Keep my details. Keep preserves the previous applied identity and the candidate page for another explicit selection. Starting a fresh manual draft deliberately discards imported provenance. Provider outcome controls simulate unavailable configuration, quota, deadline, empty and missing-runtime cases without network traffic.

`frontend/mock/entry.ts` implements the typed `entry` namespace over `frontend/mock/library.ts` records; `metadata-fixtures.ts` contains synthetic candidates. `app/mock/entry.tsx` consumes those results, and library detail exposes contributor-authorized stored-identity refresh. Public readonly review/page results cannot mutate the internal identity or original metadata snapshot. Context departure, cancellation and newer lookup work invalidate obsolete actionable handles; an applied review remains attached through selector changes. Explicit duplicate/attachment/archive confirmations bind the draft, record revision, actor/context and review lifetime. Successful shared save consumes its review and updates origins/contribution together.

The named synthetic time controls advance this service instance's **metadata clock**, not the group invitation clock. Reviews expire after ten minutes; provider fields expire after thirty UTC calendar days (`setUTCDate`), with at most twenty reviews per context. Reads and service gates clear due original fields, genres, derived pending signatures and reviews. Authored corrections, moods, numbering, provider identity, stable IDs and attributed history survive. Format-only draft changes such as `010` minutes still represent the acquired value and are cleared on expiry. Actual corrections remain. Failed refresh does not renew deadlines; a correction made while refresh waits wins. This is volatile memory modeling, not disk cleanup or a real provider policy guarantee.
