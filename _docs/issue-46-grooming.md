## Acceptance criteria

- [ ] **Actual HTTP/current own history:** declared personal operations read/write one structured record per current group/title/member through real memory services, returning contract personal/detail history projections. Authority comes from #44's live session and active account membership or selected same-group legacy profile, never caller-selected author IDs. No contribution/completion prerequisite is added for own progress/feedback. Missing/foreign/archived titles, stale profile/group/member epoch, removed/rejoined/recovered sessions and malformed inputs reject without changing another member, metadata, contribution or unrelated personal fields. Group-visible historical attribution survives contribution removal/archive/restore and participant removal.
- [ ] **Episode/timestamp/completion semantics (P01–P03):** absent episode progress remains Unknown; explicit Not started means E1/S1E1, while in-progress next-to-watch uses compatible integer coordinates 1–9999 with no continuous season or invented catalog. Explicit Unknown clears coordinates without fabricating Not started; completion/undo is independent and preserves existing position. Movie/video stopped-at uses whole seconds with absent distinct from zero: new values require usable full duration and cannot exceed it; DELETE clears only timestamp. A shortened/expired duration preserves older saved position with an honest warning and permits clearing/completion under baseline rules. No episodic timestamp, inferred completion, remaining-time pick or automatic tracking is introduced.
- [ ] **Feedback semantics (P04–P05):** save one integer rating 1–10 or explicitly clear it; blank/invalid save is not accidental clear. Notes are plain text up to 2000 Unicode code points, trim outer whitespace, preserve internal newlines and clear on blank or explicit DELETE without truncation/execution. No completion or contribution gate applies. Own saves/clears preserve all other members/fields; empty state, attributed readback, stale denial, atomic failure/rollback and idempotent absence are explicit. Ratings/notes never enter picker eligibility, ordering or semantic cycle reset.
- [ ] **Fresh eligibility and deterministic ranking (K01/K02):** input reads expose only current same-group viewers (active account members; trusted legacy profiles), never treating own profile as viewer selection. Pick requires nonempty unique authorized viewers, one exact fixed mood, whole 1–1440 available minutes and boolean rewatches defaulting off. Rebuild an authorized consistent library/progress snapshot after #45 metadata expiry; exclude archive/foreign/incomplete metadata. Reuse existing pure eligibility/ranking truth tables: unfinished Unknown blocks both modes; completed Unknown counts known-finished; off excludes any completed viewer and differing unfinished episode positions; on uses least-advanced unfinished target or E1/S1E1 restart if all completed, with correct rewatch/catch-up labels and lexicographic seasons. Use full/typical duration, never subtract timestamps. Exact requested-mood fits sort longest, then original creation time/ID; only if absent use same-mood overrun <=300 seconds (smallest first), only if both absent use different-mood within budget (longest first). Return one tier/candidate or safe no-match reasons, never both relaxations/input changes or history writes.
- [ ] **Real cycles/retries/invalidation (K03/K04):** server-owned opaque cycle/step handles bind actual session/group/epoch, canonical viewer set and inputs; clients cannot submit an eligible list/index/target as authority. Ordered same-tier title+episode targets do not repeat before explicit exhaustion/Restart. Revalidate every request including same-intent retries; one accepted logical retry replays its safe position, competing distinct stale steps conflict and failed reads/maintenance do not advance. Relevant metadata/title/contribution/selected-progress changes disclose a reset to fresh first result; ratings/notes/unselected progress and unchanged refresh bookkeeping do not reset it. Changed inputs/context or unknown/expired/evicted/process-lost/foreign handles require safe deliberate restart rather than silently widening/reusing state. Preserve 512-cycle capacity and fixed thirty-minute lifetime, privacy and no durable recommendation history.
- [ ] **Meaningful real-memory/HTTP evidence:** all twelve methods have contract/security/validation/rollback tests, a normative truth-table and differential comparison to existing pure engines, ranking boundary/tie/fallback assertions, all-tier exhaustion/restart, logical retry/race/error-no-advance and controlled expiry/eviction tests. Use #44 HTTP-created accounts/groups and #45 HTTP-created titles/reviews, then actual personal HTTP writes and current snapshots: no mocked application writes or direct frontend-mock calls as integration proof. Two isolated browser cookie contexts exercise multi-member episode/movie/video/feedback/picker flow, foreign/stale/revoked denial and no picker history/contribution writes; readonly repository assertions supplement HTTP. Owned restart loses records/cycles and rejects old sessions without DB fallback; absent paths/sentinels/privacy/cleanup remain intact. Record actual contract/focused/full-suite/typecheck/build/browser results and inherited E2E limitations; do not claim #47 UI or human testing.
