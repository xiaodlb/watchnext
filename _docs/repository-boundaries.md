# Repository boundaries for the Prisma iteration

The interfaces in `lib/repositories/contracts.ts` are intentionally portable. Domain services pass identities, group contexts and saved-title records; they never accept a Prisma client or SQLite connection. Each Prisma adapter owns its interactive transaction, applies SQLite foreign-key/busy/secure-delete connection safeguards, and leaves native-ledger checks and trigger-aware errors authoritative.

- **#49:** `lib/http-prisma/identity-store.ts` implements account/session/recovery, groups, account memberships, invitations and legacy context. It is selected only with trusted server `WATCHNEXT_HTTP_REPOSITORY=prisma` and an explicit absolute `file:` URL; see [prisma-identity.md](prisma-identity.md).
- **#50:** `lib/http-prisma/library-store.ts` persists saved titles, contributors, progress/feedback/history, metadata provenance plus durable one-time page/review contexts and guarded picker-read projections. `lib/repositories/memory-library-store.ts` is the corresponding test-only in-memory contract implementation used for differential parity checks. Its optional trusted context projection is rechecked against #49's live account membership/session revision inside each operation; #51 supplies that projection at the real HTTP composition point.
- **#51:** `lib/http-prisma/application-service.ts` is the complete runtime composition: #49 owns identity routes and #50 owns titles/history/metadata contexts/picker projection. The server selector cannot be changed by a request, cookie, URL or browser. Prisma selection has no native or memory-storage fallback.

Neither #48 nor the contracts switch the running storage or use Prisma as a generic portability claim. #49's direct identity/group repository remains the #50 prerequisite; #51 alone switches the normal application to the complete Prisma repository set.
