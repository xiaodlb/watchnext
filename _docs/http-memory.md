# Isolated HTTP memory mode — issue #44

Set `WATCHNEXT_HTTP_MEMORY=1` only in the server process before starting WatchNext to enable the `/v1` identity/group proof-of-architecture routes. For example, in PowerShell: `$env:WATCHNEXT_HTTP_MEMORY='1'; pnpm dev`.

This mode owns an empty process-memory repository. It uses real password hashing and opaque session/recovery/invitation digests, but it never opens, creates, migrates, imports or falls back to SQLite storage. Restarting the server loses all memory accounts, groups, invitations and sessions. With the setting absent, `/v1` returns a safe unavailable response; normal application routes and `/mock` keep their existing behavior.

Run `pnpm test:http-memory` for the isolated production-server evidence. It builds the current source, uses independent HTTP cookie jars for owner/member/foreign/legacy clients, checks invitation rotation and removal/rejoin identity, then restarts its owned server and proves the account session has gone. It supplies a path that must never be created as the SQLite database and removes its owned temporary files afterward.

The contract surface includes the accepted account/group operations, the shared library and metadata operations, plus #46's personal progress/feedback and picker operations. In this mode the current authenticated account member or selected legacy profile owns each personal record; request-supplied member IDs never grant authority. Personal records stay in process memory with their group/title/member history, so they are visible in a group's detail projection and disappear on restart with all other memory-mode data.

Picker requests build a fresh current memory snapshot and reuse the project's eligibility/ranking rules. A picker cycle holds only opaque process-memory authority, canonical input and position state for up to 30 minutes; it has no durable viewing history, cannot cross session/group/member context, and disappears on restart. Ratings, notes and unselected progress do not reset a cycle; selected progress, saved-title metadata and contributions do. `pnpm test:http-memory` uses two browser cookie contexts for independent progress, feedback and picker calls before proving restart loss and that no SQLite file was opened.
