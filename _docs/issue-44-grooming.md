## Goal

Implement real server-authenticated identity, account-group and separate legacy-group HTTP operations over an explicitly isolated process-memory repository, matching the `/v1` contract. This is the identity/group slice only: A01–A05, G01–G08 and L01–L04, with no synthetic authentication shortcuts, SQLite fallback or full frontend wiring.

## Acceptance criteria

- [ ] **Declared HTTP operations and real repository:** all 17 operation IDs below are reachable at their declared methods/paths and return the documented success/error/context shapes. Next Route Handlers invoke typed identity/group services through a real repository interface and memory adapter shared across those routes in the supported local server. Data is not stored in the existing SQLite service, frontend mock Maps or a hardcoded-success handler. Missing/expired/foreign/stale requests return safe distinct contract outcomes without granting access or committing partial state.
- [ ] **Real accounts/recovery/sessions:** username/password/confirmation validation matches the existing account rules; real default-cost asynchronous scrypt, random salts, supported parameter/version validation, constant-time digest comparison, unknown-user dummy work, bounded attempt maps and hash admission are preserved. Only password/recovery/session/invite digests persist in repository state; raw recovery codes/invites are once-only successful response values. Register/login rotate the presented session safely; logout revokes only the current account credential. Recovery atomically consumes current proof, replaces password/code and revokes all target sessions without auto-login; competing recovery/old-password login has one valid outcome, unrelated accounts/history remain unchanged and failure rolls everything back.
- [ ] **Request/session isolation and context:** enforce declared methods, bounded JSON/body deadline, baseline configured same-origin/Fetch Metadata guards and per-operation field semantics. Account and legacy cookies remain separate, opaque, HttpOnly/SameSite=Lax/Path=/ and Secure under HTTPS; real absolute expiry, duplicate-cookie denial, no-store/private/no-referrer sensitive responses and generic non-secret failures hold. The server derives the current actor from live credentials/membership, never supplied account/member/context claims. Account/group/mode/profile changes advance stale-intent context; away-and-back, removed/rejoined epochs and pending asynchronous work cannot revive prior authority. No secret appears in routine logs, stored browser state or retained test artifacts.
- [ ] **Account groups/invites/owner behavior:** real create/list/select/resolve/explicit-join/management/remove/rotate operations preserve stable per-account/group member identity. Anonymous resolution exposes no private group details; pending intent lasts 600 seconds and rechecks generation/context on join. Immutable creator alone can remove active nonself participants/rotate; owner status gives no contributor override. Removal immediately denies that group's access across sessions, keeps all member/reference data and records removal generation once. Rotation invalidates older links/intents while active members retain access. Rejoin requires an invite issued after removal and keeps the same member/reference identity; old confirmations fail after rejoin. Duplicate joins/removals and competing rotation respect existing idempotence, cutoff and rollback rules.
- [ ] **Separate legacy and memory lifecycle:** legacy create/resolve/list/create-profile/select use the existing name normalization, group-local uniqueness and exact palette rules; new legacy groups start without profiles. Real legacy browsing needs access but no selected profile; own future writes need a selected same-group profile. Account groups never allow profile impersonation/claiming/conversion/history copying. A documented explicit server-only memory setting starts empty isolated storage, shared by routes within that process, and never opens/initializes/imports a normal DB or reads provider secrets. Owned restart loses memory accounts/sessions/groups/intents; new requests with previous cookies deny access. Baseline production and the separate `/mock` frontend remain unchanged.
- [ ] **Meaningful contract/security/restart evidence:** actual HTTP contract tests cover all 17 IDs, methods/body/origin/cookie/auth failures, malformed/duplicate/replayed/stale/foreign inputs and atomic races/rollback; crypto uses the unchanged real cost. Two isolated browser cookie contexts exercise signup/recovery/login/logout, invite continuation/explicit join, group switching, creator removal/rotation/rejoin and separate legacy/profile access, including cross-session revocation and opaque retained history/contribution-reference fixtures. An owned server restart proves memory loss and no SQLite fallback; configured absent/default DB paths stay absent and neighboring sentinels unchanged. Record actual focused/full-suite/typecheck/build/contract/browser results and cleanup/privacy checks; do not substitute mock service calls for HTTP or claim full UI wiring/user testing. Existing pre-existing E2E intermittency is reported honestly, not hidden by retries or weakened assertions.
