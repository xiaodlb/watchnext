## Goal

Implement the shared-library and provider-review HTTP domain over the real memory repository and live identity/group services delivered by #44. Own W01–W08 and M01–M06: fourteen declared HTTP methods plus internal metadata expiry, preserving existing product identity, attribution and lifecycle behavior without implementing personal/picker mutations or frontend HTTP wiring.

## Acceptance criteria

- [ ] **Actual library HTTP reads and repository:** declared active All/Mine/archive/detail/edit-draft routes return real same-group memory records and contract DTOs, including all four content types, every contributor/name/color/inactive status, permissions, safe link/cover projection, nullable metadata and readonly attributed history. One title is one shared ID. All is default; Mine derives only from the live account member's contribution, legacy remains All-only and archive never appears active. Empty, missing, foreign, expired access and failed reads are distinct safe outcomes. Legacy browsing needs access, not an active profile; own writes require the selected same-group profile. There is no SQLite/frontend-mock fallback or fake readback store.
- [ ] **Atomic manual/shared saves:** manual save supports existing title/type/full-or-typical duration/genre/mood/numbering/link bounds. Provider namespace/ID is established by the service, never form claims. Normalized manual identity and trusted provider identity produce explicit duplicate/manual-attachment/ambiguous/archive confirmation or conflict; one member contributes at most once. Confirmation binds actor/context/member epoch, exact draft and current target revision. New title, genres/moods, provenance, review consumption and contribution commit together; stale/replayed/conflicting/racing or failed saves never create copies, overwrite another title/history or partially consume handles. Restore/save uses the same original title ID and history.
- [ ] **Contributor edits/remove/archive/restore:** only current contributors edit active shared metadata; creator status gives no override. Revisions, identity-change confirmation, active/archived identity collisions, immutable provider/group/title identity and history-compatible type/numbering rules are enforced. Expired NULL type may be filled only with unchanged compatible numbering/history and confirmation. Own-contribution removal retains others; last removal archives without deleting history. Repeated absence/restoration is safe, and restore adds only own attribution to the same record. #44 participant removal keeps its contributions/history and inactive attribution, rather than archiving titles or changing another member's records.
- [ ] **Real provider lookup/review transport:** declared YouTube title/strict-link and Kinopoisk title search/page/select/review-save/refresh routes invoke existing server-only normalized adapters with optional configuration; tests replace only outbound provider transport. Candidate selection is explicit, supplied fields stay distinguished from missing/unavailable values and safe image URLs follow current host/path rules. Opaque page/review/confirmation handles bind purpose/provider/query/current session-group-member epoch; ten-minute expiry, twenty-review context cap and five page visits apply. Malformed, foreign, expired, consumed and superseded handles cannot import identity. Manual mood/missing-runtime/type/episodic numbering/typical-duration confirmation is server-enforced; no invented episode runtime/anime classification or fabricated provider response. Missing keys/quota/deadline/network/not-found remain safe failures and manual saving stays available.
- [ ] **Origins, refresh, expiry and post-await authority:** unchanged acquired values retain provider origin/deadline; genuine corrections become authored. Refresh uses stored provider identity and live contributor permission in account mode (legacy selected profile under baseline rules), rechecks authorization/ownership after await and never overwrites newer corrections. Failed/missing/unconfigured refresh cannot renew deadlines. Internal read/save/startup/deadline maintenance clears due provider originals/derived keys/acquired genres and deletes expired reviews in memory, preserving IDs/numbering/moods/contributions/history/authored fields; reads/restore do not renew deadlines. YouTube trusted thirty-calendar-day freshness and Kinopoisk app-chosen thirty-day policy remain distinct. No expired original-value copy, public cleanup/time/reset endpoint, disk secure-deletion or powered-off maintenance claim is made.
- [ ] **Meaningful HTTP integration evidence:** tests exercise all fourteen declared methods plus internal M06, using #44-created accounts/sessions/groups and real memory writes. Cover method/origin/body/cookie/revision/member guards, foreign/revoked/rejoined access, identity/confirmation races, transactional fault rollback, malformed/replayed handles, adapter success/error fixtures, actual expiry/correction survival with a controlled clock and delayed provider response after removal/recovery/group change. Two isolated browser cookie contexts perform an actual HTTP four-type save/shared contribution/edit/remove/archive/restore and both-provider search/review/refresh journey; library reads prove same-ID/history preservation. Owned restart loses these records/handles without creating DB files; sentinels/privacy/cleanup and baseline/mock checks remain intact. Record actual contract/focused/full-suite/typecheck/build/browser results; no mocked application writes, fake UI integration, live entitlement or human-test claim.
