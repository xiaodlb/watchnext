## Implemented walkthrough and operation map

Use the existing isolated `/mock` launch from [mock frontend](mock-frontend.md); no database initialization, provider key, HTTP adapter or new package is needed. The same mounted service now exposes `groups` through `frontend/service/contracts.ts` and `frontend/mock/groups.ts`. `app/mock/groups.tsx` renders service outcomes rather than success stubs. Account and group panels invalidate each other's obsolete private views/pending requests, while legacy profile selection survives internal panel navigation in the underlying instance.

1. Sign in as `Demo.Owner` with the explicitly synthetic fixture password `synthetic password`. **Load groups** shows its active memberships. **Create account group** selects a new group and discloses its invite once; save it privately, then **Continue to groups** removes the reveal.
2. **Select Synthetic Friday friends** shows the immutable Creator, current You label, names/colors and actual Active/Inactive state. **Remove Demo.Viewer** offers named confirmation/Cancel. Removal preserves the stable member and opaque contribution/history references. A repeated removal does not update its cutoff. **Rotate synthetic invite** requires confirmation and current generation, discloses only the replacement, and preserves active members.
3. Sign in as `Demo.Viewer` (same synthetic password) to simulate a different account in this instance. Removed access is denied; the previous-generation link cannot rejoin. Resolve the newer invite and explicitly **Join pending group** to restore the same member/history. This sequential simulation is not real cross-tab authentication. Use the active-membership buttons to select groups; switching away/back invalidates old captured revisions.
4. To demonstrate anonymous continuation, sign out, enter a saved synthetic account invite in **Synthetic invite**, and resolve. No private group name is returned anonymously. Register/sign in above, **Load groups**, then explicitly Join. The intent expires after 600 seconds; controlled-clock service tests prove the exact deadline without a real wait. Unknown/revoked/missing/expired/old-context requests preserve previous valid access.
5. **Separate legacy mode** selects a distinct mode, never claiming account membership/history. **Create legacy group** returns its invite but grants no group/profile access until explicit resolution. Continue, resolve the saved value, then create/select a normalized profile with the six-color palette. A new legacy group starts without profiles or an active profile. **Load groups** after internal account-panel navigation restores the same selected legacy profile; reload/new tabs instead start independent initial fixtures. Legacy has no creator-management controls.
