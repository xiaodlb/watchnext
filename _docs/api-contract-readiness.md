## Cross-cutting decisions and exclusions

- Define the versioned base path, methods, unique operation IDs, request/response schemas, required versus absent versus nullable fields, exact enum/unit/Unicode rules and bounded bodies. Existing server-action transport is not a public HTTP contract. Choose status/error mappings consistently for validation, signed-out/access denial, private missing resources, stale/conflict/expired handles, throttling and retryable service failure; don't merely expose mock `kind` strings as security semantics.
- Specify cookie security and account/legacy separation, current server-derived group/member authority, context revisions and membership lifecycle generations. Mutation origin/method checks, no-store/no-referrer sensitive responses and once-only body disclosures must survive. IDs/expected revisions are stale-intent claims, never credentials. Do not put codes, passwords or provider keys in query strings/examples/logs.
- Keep bounded opaque search/review/confirmation/cycle handles, deadlines and consumed/replay outcomes explicit. A canceled browser request cannot promise rollback after a server commit; document lost-response recovery and domain-specific idempotent retries, particularly picker requests. Never invent a retrieval endpoint for a lost recovery code/invite.
- U01–U06 remain client interactions: local draft dirty/Replace/Keep coordination; clipboard/reveal erasure; filter/history navigation; image layout/fallback; safe external links; keyboard/focus/cancel/confirm. They trigger mapped domain operations where appropriate, not six new backend mutation groups. Synthetic `context.initialIdentity/read/reset`, scenario/outcome selectors and `entry.advanceTime` are excluded from production HTTP; actual authenticated context reads still map through A05/G06. The accepted `entry.adopt` marks an applied review: model that state in review selection/save, or an explicit real authorization transition, without adding a second visible Apply to clean autofill. Classify `entry.discard`/`cancelLookup` explicitly as local cancellation or real review invalidation with bounded idempotent behavior; never silently omit their stale-handle protection.
- M06 and backup/seed/maintenance CLI behavior are internal/operator concerns, with documented mode boundaries; do not expose reset, database paths, fake identities, time advancement or normal-data fallback. Memory restart loss versus later SQLite persistence must be explicit without changing product behavior. No provider live-access/policy/rights proof or tested PostgreSQL claim follows from contract examples.
